5. User Stories 

A user story represents a requirement from the user's perspective. 

Common format: 

“As a [user], I want [function], so that [benefit].” 

Example: 

As a student, I want to view my attendance percentage so that I can monitor my attendance. 

User stories help designers understand what users expect from the system. 

6. Use Cases 

A use case represents an interaction between an actor and the system to achieve a specific goal. 

For example, in a Smart Attendance System: 

Actor Use Cases Student Login, View Attendance, View Report Faculty Login, Mark Attendance, View Report 

Administrator Manage Users, Generate Reports 

The actual actors and use cases should be taken from the selected engineering project.
