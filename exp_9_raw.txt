###### THEORY 

###### 1. Prototype Development 

A prototype is an early model of a proposed software solution used to demonstrate its features, workflow, user interface, and interactions before complete software development. A prototype helps stakeholders and users understand how the proposed system will work. Prototype development may include: 

- « Ulscreens 

- « Navigation 

- ¢ Buttons and links 

- e Forms 

- ¢ User interactions 

- « System responses 

- «¢ Workflow implementation 

- ¢ Basic functional simulation 

The prototype should be developed based on the requirements, use cases, user stories, and workflow prepared in the previous assignments.

###### 5. Software Testing 

Software testing is the process of checking whether the proposed software or prototype behaves as expected. 

Testing helps identify: 

- ¢ Functional errors 

- e Navigation errors 

- « Missing features 

- e Incorrect outputs 

- ¢ Usability problems ¢ Broken links or interactions 

- « Requirement gap 

###### 6. Test Case 

A test case defines the input, action, expected result, and actual result used to verify a particular function.

###### 9. Validation 

Validation checks whether the proposed solution satisfies the actual needs and requirements of the intended users. 

A prototype can be validated by: 

- ¢ Requirement comparison 

- « Use case verification 

- ¢ User story verification 

- ¢ Workflow verification 

- « Test case execution 

- ¢ Peer/user feedback 

- e Usability evaluation 

The main question during validation is: 

“Does the proposed solution solve the identified problem and satisfy the user requirements?” 

###### 10. Feedback and Improvement 

Testing and validation may identify errors or areas that require improvement. The improvement process can be represented as: 

Test — Identify Issue + Analyze Cause — Modify Prototype — Retest — Validate 

At least one important improvement should be implemented based on the testing or feedback results.
